Velo Deploy inherits its security model from systemd. Each app runs in a hardened unit with no access to the rest of the system.

## Per-app Linux user

When an app is deployed, Velo creates a dedicated Linux user with no password, no login shell, and no home directory:

```
velo-<appname>:x:1001:1001::/nonexistent:/usr/sbin/nologin
```

The app runs under this user. It cannot read other users' files, and the OS will never present a login prompt for it.

## Hardened systemd unit

Each unit file includes the following directives:

| Directive | Effect |
| --- | --- |
| `ProtectSystem=full` | `/usr`, `/boot`, `/etc` are mounted read-only. |
| `ProtectHome=true` | The app cannot read `/home`, `/root`, or `/run/user`. |
| `PrivateTmp=true` | The app gets its own `/tmp` namespace. |
| `NoNewPrivileges=true` | The app cannot escalate privileges with setuid binaries. |
| `ReadWritePaths=` | Writable paths are limited to the app directory and `/tmp`. |
| `PrivateDevices=true` | The app cannot talk to raw devices. |
| `ProtectKernelTunables=true` | `/proc` and `/sys` writes are blocked. |
| `RestrictNamespaces=true` | The app cannot create new namespaces. |

`MemoryDenyWriteExecute` is **not** set. Node.js (V8 JIT) needs executable memory; enabling W^X would crash the process.

A full example:

```ini
[Unit]
Description=Velo Deploy app: my-api
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=velo-my-api
Group=velo-my-api
WorkingDirectory=/opt/deploy/apps/my-api
ExecStart=/opt/deploy/node/24/bin/node index.js
Restart=on-failure
RestartSec=5
Environment=NODE_ENV=production
Environment=PORT=3000
Environment=HOST=127.0.0.1
EnvironmentFile=-/etc/velo-deploy/apps/my-api.env

NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/opt/deploy/apps/my-api /tmp
PrivateDevices=true
ProtectKernelTunables=true
RestrictNamespaces=true

[Install]
WantedBy=multi-user.target
```

## Filesystem isolation

The app can:

- Read and write `/opt/deploy/apps/<app>/`.
- Read and write `/tmp` (private namespace).
- Read everything in `/usr`, `/etc`, `/var` (mounted read-only).
- Make outbound network connections.

The app **cannot**:

- Read other users' home directories.
- Write anywhere outside its own directory (except its own `/tmp`).
- Spawn setuid processes.
- Mount filesystems.
- Talk to raw block devices.

## Network isolation

## Secrets

<Aside type="danger" title="Do not commit secrets to Git">
	Put runtime secrets in `/etc/velo-deploy/apps/<name>.env`. Velo wires that file into the systemd unit with `EnvironmentFile=-…`, so redeploys keep your secrets. Never store them in the repository.
</Aside>

```bash
sudo install -m 0640 /dev/null /etc/velo-deploy/apps/my-api.env
sudo tee /etc/velo-deploy/apps/my-api.env >/dev/null <<'EOF'
DATABASE_URL=postgres://...
EOF
sudo systemctl restart velo-my-api
```

Custom Caddy directives that must survive a redeploy belong in `/etc/velo-deploy/caddy/<name>.snippet`. Velo imports that file into the generated vhost.

## Webhook security

`velo-deploy-watcher` requires `X-Hub-Signature-256` HMAC-SHA256. The installer writes a random secret to `/etc/velo-deploy/webhook.secret`. Set the same value as the GitHub webhook secret. Requests without a valid signature are rejected with `401`.

You can also set `VELO_WEBHOOK_SECRET` or `webhook_secret` in `config.json`.

## Supply chain

Go dependencies are pinned in `go.sum`. The release pipeline signs `SHA256SUMS` with [cosign](https://github.com/sigstore/cosign) (keyless, GitHub OIDC) and attaches `SHA256SUMS.bundle`. The installer verifies SHA256 always, and verifies the cosign bundle when `cosign` is installed.
